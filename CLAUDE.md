# KTX Driver (iOS)

Hybrid iOS app wrapping the TMS driver web page (https://driver.withktx.com) in a WKWebView,
plus native background location tracking driven by the page through a JS bridge.
Full spec: `ktxiosapp.txt` (Korean). Android reference implementation (read-only):
https://github.com/Jay-Vancouver/KTX.AndroidApp — when in doubt, match its code and docs
(CLAUDE.md, docs/WIP.md, docs/TEST.md).

## Why
iPhone drivers currently need the separate Traccar Client app; the web page cannot start/stop it
and Safari cannot send location with the screen off. Goal: the same bridge calls the TMS already
makes to the Android app work unchanged on iPhone. Distribution: App Store (Unlisted app preferred),
pilot via TestFlight, company Apple Developer account.

## Stack
Swift, SwiftUI app + UIKit WKWebView, iOS 16+, bundle ID `com.ktxtransport.driver`, name "KTX Driver".
Project generated by XcodeGen from `project.yml` (`.xcodeproj` is a build artifact, git-ignored).
Build with `xcodebuild` only. Apple frameworks only, no third-party libraries. Korean + English.

## Components
1. **WebView** — persistent WKWebsiteDataStore (cookies), camera (getUserMedia + file capture, media
   permission only for our hosts), inline media playback, back/forward swipe, external hosts/downloads
   and tel:/sms:/mailto: open in the system, UA suffix `KTXDriverApp/<version>`, Universal Links
   (`applinks:driver.withktx.com`, `applinks:www.withktx.com`, paths `/driver/*`), offline error
   screen with retry, company-blue status bar area.
2. **Location tracking** — CoreLocation background (Best accuracy, no distance filter, automotive,
   background updates, no auto-pause, blue indicator; CLBackgroundActivitySession on iOS 17+).
   Send every `interval` (default 60 s; send the first fix whose timestamp (whole seconds, as the server stores it) is ≥ interval after the last report's — iOS delivers ~1 fix/s, so Android's 5/6 rule would mean 50 s; first fix immediately).
   Heartbeat: resend last fix with current time if nothing sent for `heartbeat` (default 300 s);
   check from both location callback and timer. Significant-location-change monitoring to relaunch
   after termination/reboot.
   OsmAnd POST (form-urlencoded) to the URL from startTracking: id (10-digit phone), lat, lon (6 dp),
   timestamp (epoch s), speed (knots, 1 dp, ≥0), bearing (≥0), altitude, accuracy, batt (optional);
   "." decimal regardless of locale. 2xx ok; 4xx except 408/429 = permanent drop; else retry; 15 s timeout.
   Persistent FIFO queue (max 10,000, drop oldest), flush on NWPathMonitor reconnect, 60 s watchdog
   per send. State in UserDefaults: tracking, phone, url, interval, heartbeat, lastSentAt (ms), lastSendError(+time).
3. **Bridge `window.KtxAndroidApp`** (same name as Android) — synchronous via injected WKUserScript
   calling `prompt("ktx:"+JSON)` answered in `runJavaScriptTextInputPanelWithPrompt`.
   `startTracking(phone, url[, optionsJson]) → bool`, `stopTracking()`, `status() → JSON string`
   `{tracking,lastSentAt,permission,battery:"unrestricted",interval,heartbeat,queued,lastError}`
   (`"{}"` on disallowed pages), `requestPermissions()`, `version()`. Event `ktxappstatus` on window
   and document after permission flow, tracking change, return to foreground.
   Allowed pages: driver.withktx.com, www.withktx.com/driver/…, or admin-configured server host/path;
   checked per call, main frame only. Allowed upload hosts: https withktx.com (+subdomains) or the
   configured server's registrable domain (+subdomains); Debug also http://127.0.0.1 / localhost.
4. **Settings** — opened by left→right swipe in top 64 pt strip (not from the left 20 pt edge).
   Shows tracking state, last sent, queued, last error, permission, precise location, interval/heartbeat,
   version, re-request permission, server URL. Server URL change needs admin PIN (SHA-256 compare),
   reachability check (200–499) with "save anyway", "reset to default", reload WebView.
5. **Onboarding** — first-run screen ("Location: Always" incl. precise + Start) and an in-app
   prominent disclosure before the system location prompt (Android wording, ko/en).
6. **Updates** — App Store only; optional `/app/version.json` "ios" entry prompt.

Debug tracking without the bridge (launch arguments, Debug builds only — see `DebugCommands` in `AppDelegate.swift`):
```sh
python3 tools/osmand_receiver.py            # --status 503 / --delay 20 to test retries
xcrun simctl privacy booted grant location-always com.ktxtransport.driver
xcrun simctl location booted start --speed=25 49.2827,-123.1207 49.2000,-123.0500
xcrun simctl launch --terminate-running-process booted com.ktxtransport.driver \
  -debugTracking start -debugPhone 6045551234 -debugURL http://127.0.0.1:8099/gps -debugOptions '{"interval":10,"heartbeat":60}'
xcrun simctl launch --terminate-running-process booted com.ktxtransport.driver -debugTracking stop
```
Build: `xcodegen generate && xcodebuild -project KTXDriver.xcodeproj -scheme KTXDriver -destination 'generic/platform=iOS Simulator' build`
(Homebrew tools need `eval "$(/opt/homebrew/bin/brew shellenv)"` in non-login shells.)

Bridge test site: `python3 tools/bridge_test_server.py` (instructions in its docstring) — automatic checks of every bridge call, refusal outside /driver/, iframe isolation and ktxappstatus events.

Local test: `tools/` OsmAnd receiver (python3 http.server) at http://127.0.0.1:8099/gps (Debug-only ATS exception);
move simulator with `xcrun simctl location` or GPX. Background behavior must be tested on a real device.
