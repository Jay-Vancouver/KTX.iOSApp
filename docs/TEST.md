# 실기기 시험 체크리스트 (iOS)

KTX Driver iOS 앱을 드라이버에게 배포하기 전에 실제 아이폰으로 확인할 항목이다.
한 번 시험할 때마다 이 표를 복사해 결과를 적는다. 형식은 Android 판(`KTX.AndroidApp/docs/TEST.md`)과 같다.

| 기록 | |
|---|---|
| 날짜 / 시험자 | |
| 아이폰 모델 / iOS 버전 | (예: iPhone 16 / iOS 26.1) |
| 앱 버전 (설정 화면 "앱 버전") | (예: 1.0.0 (3)) |
| 설치 경로 | TestFlight / 개인 팀 Debug 빌드 |
| 서버 | driver.withktx.com / test.ktxtransport.com |

결과 칸에는 ✅ 통과, ❌ 실패(메모에 증상), ➖ 해당 없음을 적는다.

## 0. 준비

- [ ] 가능하면 **TestFlight 빌드(Release)**로 시험한다([RELEASE.md](RELEASE.md) C·D). Debug 빌드(개인 팀)는
      시험용 실행 인자가 있고 Universal Links가 없다 — 그 경우 2.2는 ➖, `-debugOpenURL`로 로그인한다(RELEASE.md A).
- [ ] **모바일 데이터로 시험한다.** 사무실 Wi-Fi에서는 withktx.com에 접속되지 않는다(hairpin NAT).
- [ ] 시험용 드라이버 전화번호와, 그 번호로 픽업할 시험 로드(Load#)를 준비한다.
      SMS 없이 로그인되는 시험 번호는 `docs/APP_REVIEW_NOTES.md`(git 제외)에 있다. 그 번호에는 로드가 연결되지 않으므로
      추적 시험은 드라이버 메뉴의 "Start tracking" 버튼으로 한다(3.2·5절 배송 흐름은 등록 드라이버 번호로).
- [ ] 아이폰 설정 → 개인정보 보호 및 보안 → 위치 서비스가 켜져 있는지 확인.
- [ ] 서버(TMS) 작업 확인([TMS_REQUEST_ios.md](TMS_REQUEST_ios.md)). 끝나지 않은 항목은 ➖로 두고 나중에 다시 한다.
  - (S1) 픽업 완료 화면이 `KtxAndroidApp.startTracking(전화번호, "https://www.withktx.com/gps")`를 부른다(Android와 같은 코드)
  - (S2) 배송 완료 화면이 실린 로드가 없으면 `KtxAndroidApp.stopTracking()`을 부른다
  - (S3) `/.well-known/apple-app-site-association`이 driver.withktx.com과 www.withktx.com에서 리디렉션 없이 200, 올바른 Team ID
  - (S4) 앱 안 + iPhone일 때 APK·배터리·Traccar 문구가 숨겨짐
- 앱 로그를 보려면 Mac의 **콘솔(Console.app)**에서 아이폰을 고르고 검색창에 `KTXDriver`
  (`LocationTracker:`, `FixUploader:` 줄). 선택 사항이다. 대기 건수·마지막 오류는 앱 설정 화면(8절)에서도 보인다.

## 4. 위치 전송 (추적 중)

화면을 끈 채로, 충전기에 꽂지 않은 상태가 실제와 가깝다. **백그라운드 동작은 시뮬레이터로 확인할 수 없으므로 이 절이 가장 중요하다.**

| # | 할 일 | 기대 결과 | 결과 | 메모 |
|---|---|---|---|---|
| 4.1 | 화면을 끄고 **5분** 둔다 | 지도에 약 1분 간격으로 점이 계속 찍힌다 | | |
| 4.2 | 화면을 끄고 주머니에 넣은 채 **30분 이상** 운전 | 점이 끊기지 않는다. 카드가 회색(10분 무수신)으로 바뀌지 않는다 | | |
| 4.3 | **하트비트**: 추적 중 한곳에 **10분** 정차(화면 끔) | 새 위치가 적어도 약 5분마다 한 번은 서버에 도착(카드가 회색이 되지 않음) | | |
| 4.4 | **오프라인**: 비행기 모드 **10분**(화면 끔) → 해제 | 해제 후 1분 안에 비행기 모드 동안의 점들이 **순서대로** 도착(지도의 빈 구간이 채워짐) | | |
| 4.4a | 4.4 중 앱 설정 화면(상단 띠를 좌→우로 밀기) | "대기 중인 위치"가 늘고 "마지막 전송 오류"에 원인(예: `URLError -1009 (offline)`). 연결 후 대기 0건, 오류 "없음" | | |
| 4.5 | 다른 앱(지도, 카카오톡, 음악)을 오래 쓰다 돌아옴 | 그동안에도 점이 찍혀 있다 | | |
| 4.6 | (서버가 options를 넘기면) `startTracking(..., JSON.stringify({interval: 30}))` | 지도에 약 30초 간격 점. 설정 화면 "전송 간격 / 하트비트"가 30초 / 300초 | | |
| 4.7 | 저전력 모드를 켜고 4.1 반복 | 점이 계속 찍히는지(간격이 늘어나면 메모) | | |
| 4.8 | 8~10시간 근무 후 배터리 | 설정 → 배터리 → KTX Driver 사용량(화면 켜짐/백그라운드)을 메모 | | |

## 9. 알려진 제약 (iOS)

- 앱 전환기에서 **쓸어 올려 종료**하면 iOS는 위치 이벤트로도 앱을 다시 깨우지 않을 수 있다(6.1).
  드라이버 안내: "KTX Driver를 쓸어 올려 종료하지 마세요." — 실기기 결과로 확정한다.
- 재시동 후 **첫 잠금 해제 전**에는 앱이 저장된 추적 상태를 읽지 못해 다시 시작하지 못할 수 있다(6.4).
- 재시작(6.1·6.3)은 significant location change(대략 수백 m 이상 이동)에 의존하므로, 정차 중에는 다시 시작되지 않는다.
- 백그라운드에서는 iOS가 주는 위치 갱신에 맞춰 보내므로, 정차 중 하트비트가 정확히 5분이 아닐 수 있다(4.3).
- iOS에는 배터리 최적화 예외 설정이 없다. `status().battery`는 항상 `"unrestricted"`.
- 무료 개인 팀 빌드는 7일 뒤 실행되지 않고 Universal Links가 없다(RELEASE.md A).
